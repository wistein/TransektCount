1. Introduction

TransektCount should support you when monitoring butterflies and day-flying moth in European transects.
It allows to register individuals species-specific, separated by gender and metamorphic stages per transect section according to the European Butterfly Monitoring Scheme.
Transect sections must be selected manually but can optionally be indicated automatically via GPS.
It offers prepared result outputs and substitutes your field book, pencil, and if applicable a camera for documentary pictures.

Databases can be created individually for transect sections and expected butterfly species. For this purpose, a comprehensive, illustrated list of species is included. The internal database is survey-related, i.e. a new database instance is used for each survey.

The recorded data (metadata, counts and annotations) can be entered into a butterfly monitoring system, e.g. at
https://web.app.ufz.de/tagfalter-monitoring
either by reading them in order from the results page or by exporting them to an MS Excel spreadsheet, transferring that to a computer for more conveniently reading or your own processing.

The app is published with source code and documentation as open source on
https://github.com/wistein/TransektCount.
It has neither tracking nor advertising functions and does not make use of Google Play Services, but requires permits for its serviceable functions:

- Storage access which is needed for importing species data and DB files, exporting data and the counting results to DB, XLSX or CSV files,
- wakelock to hinder the app from being switched off by the system when inactive, but get dimmed and get an insensitive screen when pocketed or held near the body and
- optionally exact location tracking by GPS to recognize the sections and to inform about a section transition.


2. Setting up

Before initial use you should adapt the app settings to your liking
(→ 4. Further Functions).

Initially ignore item “Remind transect sections by GPS”, as certain preconditions have to be met before
(→ 5. GPS Usage).

Then adapt the preliminary species list of the 1. transect section to the expected species in your transect with the species list editing functions (Add, Remove or Edit).

To do this, click "Counting" on the Starting page and then select "Sect 01". The counting page of section 1 opens. Use the editing icons (Add species, Remove species and Edit Terms) in the header on the counting page.

All 3 editing pages offer a preselection to ease the selection of a distinguished species. Enter 2 or more letters of the scientific species name and then click the Search-button to limit the shown list. You may enter more letters and click the Search-button again to further reduce the selection list.

On the blue "Add Species" page tag the species to add. Changes take effect by the (+)-button in the head line (notice that the selected species disappear from the scroll-down list).

At the end of the scroll-down list, a placeholder for an indeterminate species (NN) can be adopted and edited later after determination, if necessary.

On the red "Remove Species" page tag the species to remove and tip on the Delete-button.

On the "Edit Terms" page you may edit the current section name and the terms of each species. (Scientific and local species names, codes generally five digits with leading zeros, as you can see in the following species list table excerpt).

(Part of a species list)
---------------------------------------------------
...
Pieris rapae ..................... 06998
Small white
Pieris napi ....................... 07000
Green-veined white
Pie. napi/rap. compl. ...... 07001*
Small whites compl.
...

The codes will be used as an option to sort the list and as a reference to show corresponding butterfly icons.
The codes derive from the numbering scheme of European butterflies by Karsholt/Razowski, as used e.g. in the German Lepiforum (https://lepiforum.org).

The *-sign attached to code 07001 in the table above indicates a complex of species that are difficult to distinguish. For sorting purposes, the larger code within the group should be used for such groups.
Caution: A wrong code shows "N/A" or a wrong picture. If necessary, see the "List of Coded Butterflies.pdf" on
https://github.com/wistein/TransektCount/tree/master/docs.

In the next step, you could enter some metadata like transect-No. or inspectors name. Click on "Edit Metadata" and save the input by clicking the save icon.

Once this section list is complete, you can add copies for all remaining transect sections by the add button on top of the section list, and name each section appropriately, if possible in the order you will walk the transect (e.g.: Sect 02, Sect 03, ...).

When you have created the section lists for all your transect sections and entered the general metadata, the database is ready for export as a "Basic Database".
To do this, use the function "Export as Basic DB" in the main menu of the starting page.
By that you have a copy of the prepared empty database saved as "Basic Database" (transektcount0_dl_Tr-No.db) with 'dl' as data language and ‘Tr-No’ as Transect No. in the app's data directory "Documents/TransektCount".
The app data directory is created during the first app call. When uninstalling TransektCount you will not lose your data as this directory remains untouched.

Exporting as Basic DB ignores all counts, notes and inspection-related metadata. The Basic DB serves as a template for future inspections. To prepare a future monitoring inspection you will only need to enter the inspection-specific metadata (date, start time, temperature, wind and clouds).

The Basic DB can be changed, supplemented and exported anytime. Changes of species always affect all sections to maintain consistency. However, the section name will only be changed for the current section.
Note: The file names of the Basic DBs always start with the string "transektcount0" ("transectcount" with a trailing "0").

Alternatively you can import and adapt a self-created Basic DB for your transect. Or you may substitute the species list by importing a previously exported species list from TransektCount or TourCount (if installed). Examples for downloading, partly from other European countries than Germany, are provided on
https://github.com/wistein/TransektCount/tree/master/docs.

Copy them to the app’s data directory "Documents/TransektCount" and import and edit them in TransektCount suitably. Changes to the species always affect all existing section lists.

The file naming convention for the exported TransektCount files:

- Basic DB:       transektcount0_dl_Tr-No.db
- Current DB:   transektcount_dl_StartDate_Tr-No.db
- Result:           Transect_dl_StartDate_Tr-No_os.xlsx
                          (or .csv)
- Species list:  species_dl_Tr-No_CurrentDate.csv

with

- blue = fixed string parts.
- dl = data language of local species names
      ("de", "en", "es", "fr", "it"),
- Tr-No = transect name
      (filtered for filename conformity),
- StartDate = date of the inspection start
      (YYYYMMDD-hhmm).
      If not specified the current storage date,
- os = output sorting code ("n" names, "c" codes,
      "sn" section and names or
      "sc" section and codes).
- CurrentDate = current storage date
      (YYYYMMDD-hhmm).


3. Usage

Start with "Edit Metadata". Fill in the relevant metadata for the specific transect inspection.
Das aktuelle Datum und die momentane Uhrzeit kann durch Antippen des jeweiligen Felds eingegeben werden.
You may enter the current date and time by clicking the related field or enter any date and time by long pressing the related field. Finish with the save button.

Then select "Counting". The transect sections list is displayed here.
Select the relevant transect section by clicking the section name. The counting page for the first species in the sorted species list of the section appears.

As counting of butterflies ought to be distinguished between those within the imaginary count area (a cubus of 5 m length of edges in front of you) and butterflies outside this area, you have 2 separate sets of counters (Internal and External of Counting Area).

To count just select the species in the scroll list, and tip on the appropriate (+)-button of the category (♂|♀, ♂, ♀, Pupa, Larva, Ovo) of the species. The (-)-buttons allows for corrections.

Each count is stored immediately. While storing the first count in a section, the current date and time will be stored either in the section list. The date will then be shown in the list of sections and indicates a successful inspection of that section. The time can be helpful later when assigning document photos.

The Pencil button underneath the species name row of the counting page opens the section specific species editing page that lets you set its counters to any value (e.g. for estimated mass occurrences) and edit a note for the species in that section. For the latter, common entries can be selected from a pop-up list with a single click.

If you enter a species related note this will be shown on the counting page in an extra line beneath the counting field and is inserted into the results table (e.g.: "Photo").
If you enter a “0” in this field, the species will also be listed in the results later, despite a count of 0.

To move back one page you generally can use the ⬅-button. To make sure to save changed content you should go back by tipping the respective Add, Delete or Save button.

Before finishing TransektCount after an inspection you should complete the metadata with the ending values for time, temperature, wind and clouds. Then use an "Export results" option in the start page menu to save the current inspection results as an .xlsx (MS Excel table) or as a .csv (comma separated values, table textfile). The files will be named with data language, inspection start date and time, transect No. and output sorting code and saved as "Transect_dl_StartDate_Tr-No_os.xlsx" or ".csv" in the directory "Documents/TransektCount". Without a given start time the current date and time ist used.

When using GPS, a short message indicating the distance to the transect is displayed after the app is started and after the first GPS fix. When a transect section is reached, an acoustic signal and a message inform you about the current transect section. You are also informed each time there is a change of transect section.

The section must still be selected manually, but GPS detection supports timely switching to the current transect section, so that accidental incorrect section assignment during counting occurs less frequently.

On the “Transect sections” page, the name of the newly recognized section is marked in blue after GPS recognition.

Finally, the "Counting Results“ page shows your results sorted either by species or sections according to the selected Output sort option. Here, in a scroll view you see beneath the metadata of the inspection the totals per category and all the species which got counts.
You can enter this page from the Starting page with "Show Results" or the Eye-symbol in the app bar. It may take a second to show up.

To move back one page you can use the Back-button or arrow in the left upper corner. To make sure to save edited content you should click the Add, Remove or Save button if the page has one.

With large amounts of data, the app's response can be somewhat delayed for e.g. import functions or when calling up the results page, as extensive calculations are running in the background. This is indicated by a short message "View gets calculated …“.

If the message "TransectCount not responding" appears, please reply with "Wait".


4. Further functions

The app menu on the starting page has Settings, Reset, Import, Export, Info and Help functions.

In "Settings" you may adapt the look an feel in some aspects to your wishes, e.g. sorting order of lists and data export, left-/right-hand counting page or sounds and haptic button feedback. Here you can also optionally activate the GPS function for automatic indication of the current transect section, provided a prepared GPX track file with tracks of all transect sections has been imported. For detailed information see “5. GPS Usage”.

To prepare for a new inspection you may use "Reset Data" to reset the inspection-specific metadata and count data of the transect. All other transect-specific data remains untouched.
Alternatively you may import the Basic DB, another transektcount-DB or a species list.

Android-specifically, TransektCount stores the data in an internal SQlite DB in the app's own protected storage area that is not accessible by the user. Therefore, it is necessary to import/export data from/to files in a user accessible storage area.

Starting with app version 5.0.6, DB files are exported with a field for identifying the data language for local species names (German, English, French, Italian, and Spanish). For imported DB files created prior to this update, the correct data language should be selected via "Settings" to ensure proper processing.

The "Import Basic DB" function lets you select and import a DB file that was exported as a template for a certain transect.

When exporting data, the transect name (if it exists in the metadata) will be inserted into the name of the exported file. Here, any characters that violate the filename conventions are removed as necessary.

With "Export Basic DB" you may export the current internal DB without any inspection-specific data into a Basic DB file "transektcount0_dl_Tr-No.db" to "Documents/TransektCount". This is reasonable if permanent changes have been made to the transect structure or if species have been removed or new ones added.

With "Import DB" any appropriately named TransektCount DB can be selected and read into TransektCount.
Mind: The file name of a TransektCount-DB with counting data must always begin with "transektcount_" (e.g. "transektcount_en_NW-5309-03.db"), otherwise the DB cannot be imported.

"Export Current DB" writes a copy of the DB with all currently contained data as "transektcount_dl_StartDate_Tr-No.db" into "Documents/TransekCount". If exists, the start date and time of the tour gets inserted into the filename. Otherwise, the current date gets inserted. The transect-No. is inserted into the filename but eventually gets cleaned up to remove characters that violate file naming conventions.

The function "Import Species List" lets you select and import an available species list. The metadata is retained during import, but all counting data is deleted. If the TourCount app is installed, the exported species lists can be imported mutually. The file manager can be used to rename these as required.
Starting with app version 5.0.5, the species list has been updated to include the data language. The available data languages are German, English, French, Italian, and Spanish. When local species names were available, they have been included for the species listed in the app.
There is one drawback when importing a species list created for or with older versions. To work as expected you have to set the correct data language manually in the Settings.
Mind: The file name of a species list must always begin with "species_", otherwise the list cannot be imported.

With "Export Species List" the current species list can be exported as a CSV file (CSV = Comma Separated Values text file) "species_dl_Tr-No_CurrentDate.csv".

If you imported a species list that was exported from an app version earlier than 5.0.5, you should set its data language in Settings and then re-export the list. After that, the data language will be automatically detected and set in the future.

"Import GPS Track" reads a prepared gpx Track file (e. g. transektcount_t1.gpx) from directory "Documents/TransektCount". In "5. GPS Usage" is shown how to create and handle a GPX file.

The functions "Export Results (xlsx)" and "Export Results (csv)" write the counting results with the metadata of the inspection into the formatted Excel spreadsheet file “Transect_dl_StartDate_Tr-No_so.xlsx” or the pre-formatted table textfile ".csv" to “Documents/TransektCount”. The file names will preferably include the start date of the inspection; otherwise, they will include the current date.

The table can be sorted in advance by species name, species code, and section using the “Sorting the Results” option in the TransektCount settings. This simplifies data entry depending on the design of the input form on a monitoring website, such as
. https://web.app.ufz.de/tagfalter-monitoring/. the table can be sorted beforehand (depending on your requirements by species name or code and section) using the results sorting option in TransektCount's settings.

The exported result files could be viewed and, to a limited extent, edited in a spreadsheet app such as Collabora (open source, free, based on LibreOffice). It is available in the Collabora Office Store (an additional package source in the F-Droid app store), in the Play Store, or directly at https://www.collaboraoffice.com/downloads/).

The exported ".xlsx" or ".csv" result files can also be transferred to a PC for further processing and loaded or imported into a spreadsheet program (tested with MS Excel, LibreOffice Calc and Softmaker PlanMaker).

IT-affine users may transfer the exported ".db" files from "Documents/TransektCount" to a PC.
There you may examine and edit a .db-file manually or per SQL script with a free tool like "DB Browser for SQLite"
(https://sqlitebrowser.org).
Some useful example SQL scripts are published in the docs directory of the GitHub TransektCount project site
https://github.com/wistein/TransektCount/tree/master/docs.

Under "App Info" you may find general app info, the email address of the author and the history.

Under "Licenses" you find the license notes for code and figures.

The option menu of the counting page provides a "Photo" function to quickly take a photo and a "Share" function for sending TransektCount related notes using a standard app, like SMS or email.

Optionally, the counter view is temporarily turned off by means of the proximity sensor when the phone is pocketed or closely held to the body. This saves energy, prevents unwanted inputs and recalls the app into its current state immediately when used again.

The app shows several short pop-up messages in 4 categories:

- Error        (e.g. with a database problem).
- Warning (e.g. in the event of an invalid entry).
- Note        (e.g. if an action might last longer).
- Info          (e.g. after a successful process).


5. GPS Usage

Automatic section recognition in the transect is performed by comparing the current position with the track coordinates of the transect sections in a transektcount_xxx.gpx file. If the current position is no further than e.g. 5 m (default setting) away from a section track point, the section is indicated for registration. GPS inaccuracies must unfortunately be accepted. Contact between two transect sections should be avoided and gaps of approx. 5 m between sections are recommended.

To strike a balance between performance and power consumption, you can set the "Min. distance for GPS update" between 0 and 5 m (default: 5 m) and the "GPS polling interval" between 1 and 10 seconds (default: 3 seconds).

The preset deviation radius "Max. Distance of track deviation" can be set between 2 and 10 m (default: 5 m) to accommodate the device's GPS accuracy.


5.1 Creating the track file for TransektCount

A transect route can be recorded using a free smartphone app such as CoMaps or another hiking map app that can export the recorded track with sufficient accuracy in GPX format. It is advisable to record the transect route several times on-site with the smartphone. The recorded track should match the route shown on the map. Discrepancies that are similar across repeated recordings of the transect route suggest inaccuracies in the map.

In addition, named waypoints can be set at the section boundaries during recording. The recordings are intended to serve as a guide for the section tracks that will subsequently be drawn manually.

On Windows:

You may use the free BaseCamp program from Garmin. Load a suitable free map based on OpenStreetMap. Import the recorded transect GPX track(s).

When manually drawing track sections in BaseCamp, you should use the highest possible zoom level, as this allows you to achieve optimal spacing of approximately 2 meters between individual track points when drawing a track. This ensures sufficient accuracy for coordinate matching to identify sections within the app.

The transect sections must be drawn as new section tracks in the same number and order as they are listed in TransektCount. During import of the created .gpx file in TransektCount, they are assigned to the existing transect sections in this order. Naming them as shown in Fig. 16 is intended solely for your own reference.

Draw each section track with the individual track points spaced approximately 2 meters apart along the imaginary, averaged line of the recorded route. Leave a gap of approximately 5 meters between each section track.

Once all the section tracks are complete, delete the transect GPX route(s) that were previously imported from your smartphone.

The drawn transect tracks can then be exported to the file “transektcount_xxx.gpx”, where the prefix “transektcount” is significant and “xxx” serves as a placeholder for a transect name.

Fig. 16 shows a screenshot of BaseCamp with the section tracks of a transect example.

On Linux:

You can use the Viking program for this. Although its user interface differs significantly from BaseCamp, the result is just as useful. The procedure is the same as that described in “On Windows”.

In Viking, the result must be exported as a “Single GPX File”.


5.2 Import of the track file in TransektCount

Copy the created transektcount_xxx.gpx track file to "Documents/TransektCount" on the smartphone. There it is expected by the app for import.

If the track file has been created correctly, the "Import GPS Track" command will acknowledge this with the message “The GPX file has been imported.”

Finally, activate the item "Indicate transect section by GPS" under Settings and, if necessary, adjust the sensitivity under "Maximum GPS deviation allowed".


5.3 Notes

It is advisable to record the transect track a couple of times with your smartphone on site as a control supplement in preparation for manually creating the GPX file. The recorded tracks should correspond as closely as possible to the route on the map. Larger deviations, which are similar for several recordings, indicate inaccuracies in the map.

Manual drawing of track sections in BaseCamp should be done at a high zoom level, as this ensures optimal spacing of approx. 2 m between individual track points and sufficient accuracy for coordinate matching to determine sections within the app.

The transect sections should be drawn in the same number and sequence as they are listed in TransectCount. During import, they are assigned to the existing transect sections in this order.

As the number of transect sections must be equal to the number of tracks, adding a new transect section is only possible as long as no tracks have been imported. Therefore, before adding a new transect section existing tracks must be deleted from the database using the "Delete GPS Track Data" function.

After adding a new section, the track file assigned to the transect must also be supplemented with the track of the new section in BaseCamp, Viking or a similar application and re-imported into TransektCount.

When a transect section is deleted, the corresponding section track is also deleted from the database.
