1. Introduction

TransektCount is designed to assist transect counters in transect surveys in accordance with butterfly monitoring programs in Europe.

It can be used to record individuals per transect section on a species-specific basis and separated by gender and metamorphic stages according to the European Butterfly Monitoring Scheme method.
Transect sections must be selected manually but can optionally be indicated automatically via GPS.
TransektCount offers prepared result outputs and substitutes your field book and pencil, and if applicable a camera for documentary pictures.

Database files will be created individually for transect sections and expected butterfly species. For this purpose, a comprehensive, illustrated list of species is included. The internal database is survey-related, i.e. a new database instance is used for each survey.

The recorded data (metadata, counts and annotations) is prepared as a report for an easy manual transfer into a butterfly monitoring system, e.g. at
https://web.app.ufz.de/tagfalter-monitoring.
It can be read directly on the smartphone or exported as an MS Excel spreadsheet and transferred to a PC, where it can be viewed or processed more easily.

The app is published with source code and documentation as open source on
https://github.com/wistein/TransektCount.
It does not require an internet connection, contains no tracking or advertising features, and does not use Google Play services, but requires the following permits for its serviceable functions:

- All files access which is needed for importing DB files,
   species lists, and track files (DB, CSV or GPX files),
   and for exporting DB files, species lists, and results
   (DB, CSV or XLSX files),
   exclusively in the TransektCount data directory and,
   if applicable, in the TourCount data directory),

- optionally Wakelock to hinder the app from being
   switched off by the system when inactive, but get
   dimmed and get an insensitive screen when pocketed or
   held near the body and

- optionally exact GPS location tracking to recognize the
   sections and to signal a section transition.


2. Setting Up

When starting the app for the first time, permission for saving data must be granted. TransektCount reads from and writes exclusively to the public directory Documents/TransektCount, which is created when the app is launched for the first time (and to Documents/TourCount if the companion app TourCount is installed. This data directory is not deleted when TransektCount is uninstalled; the data stored there is retained.

Later, if you have a transect track file and want GPS-controlled section detection, the permission for location recognition must be given. For more reliable location tracking on longer transects, you may optionally activate “Allow all the time” in the System Settings. This prevents Android from terminating the location tracking service during longer breaks in app usage.

Before initial use you should adapt the app settings to your liking
(→ 4. Further Functions).

Initially ignore item “Indicate transect sections by GPS”, as certain preconditions have to be met before
(→ 5. GPS Usage).

Then adapt the preliminary species list of the 1. transect section to the expected species in your transect with the species list editing functions (Add, Remove or Edit).

To do this, click on the Starting page "Counting" and then select "SECT 01". The counting page of section 1 opens. Use the editing icons (Add species, Remove species and Edit Terms) in the header on the counting page.

All 3 editing pages offer a preselection to ease the selection of a distinguished species. Enter 2 or more letters of the scientific species name and then click the Search-button to limit the shown list. You may enter more letters and click the Search-button again to further reduce the selection list.

On the blue "Add Species" page tag the still needed species to add. Changes take effect by the (+)-button in the head line (notice that the selected species disappear from the scroll-down list).

At the end of the scroll-down list, a placeholder for an indeterminate species (NN) can be adopted and edited later after determination, if necessary.

On the red "Remove Species" page tag the species to remove and tip on the Delete-button.

On the green "Edit Terms" page you may edit the current section name and the terms of each species. (Scientific and local species names, codes generally five digits with leading zeros, as you can see in the following species list table excerpt).

(Part of a species list)
---------------------------------------------------
...
Pieris rapae ..................... 06998
Small white
Pieris napi ....................... 07000
Green-veined white
Pie. napi/rap. compl. ...... 07001*
Small whites compl.
...

The codes will be used as an option to sort the list and as a reference to show corresponding butterfly icons.
The codes derive from the numbering scheme of European butterflies by Karsholt/Razowski, as used e.g. in the German Lepiforum (https://lepiforum.org).

The *-sign attached to code 07001 in the table above indicates a complex of species that are difficult to distinguish. For sorting purposes, the larger code within the group should be used for such groups.

Caution: A wrong code will show a "N/A" or a wrong picture. If necessary, see the "List of Coded Butterflies for TourCount and TransektCount.pdf" featuring local names in 5 European languages on
https://github.com/wistein/TransektCount/tree/master/docs.

Once this list is complete, you can add copies for all remaining transect sections by the add button on top of the section list, and name each section appropriately, if possible in the order you will walk the transect (e.g.: Sect 02, Sect 03, ...).

In the next step, you could enter some metadata like transect-No. or inspectors name. Click on "Edit Metadata" and save the input by clicking the save icon.

When you have created the section lists for all your transect sections and entered the general metadata, the database is ready for export as a "Basic Database".
To do this, use the function "Export as Basic DB" in the main menu of the starting page.
By that you have a copy of the prepared empty database saved as "Basic Database" (transektcount0_dl_Tr-No.db) with 'dl' as data language and ‘Tr-No’ as Transect No. in the app's data directory "Documents/TransektCount".
The app data directory is created during the first app call. When uninstalling TransektCount you will not lose your data as this directory remains untouched.

Exporting as Basic DB ignores all counts, notes and inspection-related metadata. The Basic DB serves as a template for future inspections.

The Basic DB can be changed, supplemented and exported anytime. Changes of species always affect all sections to maintain consistency. However, the section name will only be changed for the current section.
Note: The file names of the Basic DBs always start with the string "transektcount0" ("transectcount" with a trailing "0").

To prepare a future monitoring inspection you will only need to enter the inspection-specific metadata (date, start time, temperature, wind and cloud cover).

Alternatively you can import and adapt a self-created Basic DB for your transect. Or you may substitute the species list by importing a previously exported species list from TransektCount or TourCount (if installed). Examples for downloading, partly from other European countries than Germany, are provided on
https://github.com/wistein/TransektCount/tree/master/docs.

Copy them to the app’s data directory "Documents/TransektCount" and import and edit them in TransektCount suitably. Changes to the species always affect all existing section lists.

The naming convention for the files exported by TransektCount:

- Basic DB:       transektcount0_dl_Tr-No.db
- Current DB:   transektcount_dl_StartDate_Tr-No.db
- Result:           Transect_dl_StartDate_Tr-No_os.xlsx
                          (or .csv)
- Species list:  species_dl_Tr-No_CurrentDate.csv
- Track:             transektcount_xxx.csv

with

- blue: fixed string parts.
- dl: data language of local species names
   ("de", "en", "es", "fr", "it"),
- Tr-No: transect name
   (filtered for filename conformity),
- StartDate: date of the inspection start
   (YYYYMMDD-hhmm).
   If not specified the current storage date,
- os: output sorting code ("n" names, "c" codes,
   "sn" section and names or
   "sc" section and codes).
- CurrentDate: current storage date
   (YYYYMMDD-hhmm).
- xxx: Track name (e.g. transect No., but
   compatible with the filename convention)


3. Usage

Start with "Edit Metadata". Fill in the relevant metadata for the specific transect inspection.
You may enter the current date and time by clicking the related field or enter any date and time by long pressing the related field. To suppress unreal values for temperature, wind or clouds, plausibility checks are done when saving and refuse saving until suitable values are entered. The percentage value entered for cloud cover is rounded to the nearest ten when saved. Finish with the "Save" button.

Then use "Counting". The transect sections list is displayed here.
Select the relevant transect section by clicking the section name.

The counting page for the first species in the sorted species list of the section appears. After clicking the butterfly icon select the respective species from the scroll list.

As counting of butterflies ought to be distinguished between those within the imaginary count area (a cubus of 5 m length of edges in front of you) and butterflies outside this area, you have 2 separate sets of counters (Internal and External of Counting Area).

To count just select the species in the scroll list, and tip on the appropriate (+)-button of the category (♂|♀, ♂, ♀, Pupa, Larva, Ovo) of the species. The (-)-buttons allows for corrections.

Each count is stored immediately. While storing the first count in a section, the current date and time will be stored either in the section list. The date will then be shown in the list of sections and indicates a successful inspection of that section. The time can be helpful later when assigning document photos.

The Pencil button underneath the species name row of the counting page opens the section specific species editing page that lets you set its counters to any value (e.g. for estimated mass occurrences) and edit a note for the species in that section. For the latter, common entries can be selected from a pop-up list with a single click.

If you enter a species related note this will be shown on the counting page in an extra line beneath the counting field and is inserted into the results table (e.g.: "Photo").
If you enter a “0” in this field, the species will also be listed in the results later, despite a count of 0.

To move back one page you generally can use the ⬅-button. To make sure to save changed content you should go back by tipping the respective Add, Delete or Save button.

Before closing TransektCount after an inspection you should complete the metadata with the ending values for time, temperature, wind and clouds. Then use an "Export results" option in the start page menu to save the current inspection results as an .xlsx (MS Excel table) or as a .csv (comma separated values, table textfile). The files will be named with data language, inspection start date and time, transect No. and output sorting code and saved as "Transect_dl_StartDate_Tr-No_os.xlsx" or ".csv" in the directory "Documents/TransektCount". Without a given start time the current date and time is used.

When using GPS, a brief message indicating the distance to the transect is displayed after the app is launched and after the first GPS fix. When a transect section is reached, an acoustic signal and a message inform you about the current transect section. The app provides the same notification each time there is a change of transect sections.

The section must still be selected manually, but GPS detection supports timely switching to the current transect section, so that accidental incorrect section assignment during counting occurs less frequently.

On the “Transect sections” page, the name of the newly recognized section is marked in blue after GPS recognition.

Finally, there is the "Counting Results“ page showing your results sorted either by species or sections according to the selected Output sort option. Here, in a scroll view you see beneath the metadata of the inspection the totals per category and all the species which got counts.

Depending on the selected output sorting option, the included list of individuals can be sorted and displayed either by species name, species code, section and name, or by section and code.

You can enter this page from the Starting page with "Show Results" or the Eye-symbol in the app bar. It may take a second to show up.

When you have large lists or have collected big amounts of data the app may delay the start of pages, especially the results page, as this needs heavy calculations. This will be indicated by a short message "View gets calculated …“.

If the message "TransectCount not responding" appears, please reply with "Wait".


4. Further Functions

The app menu on the starting page has Settings, Reset, Import, Export, Info and Help functions.

In "Settings" you may adapt the look an feel in some aspects to your wishes, e.g. sorting order of lists and data export, left-/right-hand counting page or sounds and haptic button feedback. Here you can also optionally activate the GPS function for automatic indication of the current transect section, provided a prepared GPX track file with tracks or track segments of all transect sections has been imported. For detailed information see “5. GPS Usage”.

To prepare for a new inspection, the inspection-specific metadata and all counting data can be deleted using "Reset Data". All other transect-specific data remains untouched.
Alternatively you may import the Basic DB, another transektcount-DB or a species list.

Android-specifically, TransektCount stores the data in an internal SQlite DB in the app's own protected storage area that is not accessible by the user. Therefore, it is necessary to import/export data from/to files in a user accessible storage area.

Starting with app version 5.0.6, DB files are exported with a field for identifying the data language for local species names (German, English, French, Italian, and Spanish). For imported DB files created prior to this update, the correct data language should be selected via "Settings" to ensure proper processing.

The "Import Basic DB" function lets you select and import a DB file that was exported as a template for a certain transect. Its name begins with "transektcount0".

With "Export Basic DB" you may export the current internal DB without any inspection-specific data into a Basic DB file "transektcount0_dl_Tr-No.db" to "Documents/TransektCount". This is reasonable if permanent changes have been made to the transect structure or if species have been removed or new ones added.

With "Import DB" an exported or appropriately named TransektCount DB containing count data can be selected and read into TransektCount.
Note: The file name of a TransektCount-DB with counting data must always begin with "transektcount_" (e.g. "transektcount_en_NW-5309-03.db"), otherwise the DB cannot be imported.

"Export Current DB" writes a copy of the DB with all currently contained data as "transektcount_dl_StartDate_Tr-No.db" into "Documents/TransekCount". If available in the metadata, the transect name and the date and time the survey began are included in the filename. If the start date is missing, the current date is used. If necessary, the transect name is stripped of any characters that violate the filename conventions.

The function "Import Species List" lets you select and import an available species list. The metadata is retained during import, but all counting data is deleted. If the TourCount app is installed, the exported species lists can be imported mutually.

Starting with app version 5.0.5, the species list has been updated to include the data language. The available data languages are German, English, French, Italian, and Spanish. When local species names were available, they have been included for the species listed in the app.
For imported species list files created prior to this update, the correct data language should be selected via “Settings” to ensure proper processing.
Note: Importing a species list deletes all current counting data. The file name of a species list must always begin with "species_", otherwise the list cannot be imported.

With "Export Species List" the current species list can be exported as a CSV file (CSV = Comma Separated Values text file) "species_dl_Tr-No_CurrentDate.csv". Here, too, the transect name is inserted if it exists in the metadata and, if necessary, cleaned up to remove characters that violate the filename conventions.

If a species list was imported that was exported from an app version earlier than 5.0.5, its data language can be set later under “Settings”, and the list can be exported again. After that, its data language will be automatically detected and set in the future.

"Import GPS Track" reads a prepared gpx Track file (e. g. transektcount_t1.gpx) from directory "Documents/TransektCount". In "5. GPS Usage" is shown how to create and handle a GPX file.

The functions "Export Results (xlsx)" and "Export Results (csv)" write the counting results with the metadata of the inspection into the formatted Excel spreadsheet file “Transect_dl_StartDate_Tr-No_so.xlsx” or as a structured, comma-separated table textfile ".csv" to “Documents/TransektCount”. The file names will include the start date of the inspection, if available; otherwise, it will include the current date..

To simplify data entry depending on the design of the input form of a central monitoring website, such as
https://web.app.ufz.de/tagfalter-monitoring/
the count data part of the table can be sorted beforehand using the “Sorting the Results” option in TransektCount’s settings. The output sorting options are: by species name, species code, as well as section + species name and section + species code.

The exported result files could be viewed and, to a limited extent, edited in a spreadsheet app such as Collabora (open source, free, based on LibreOffice). It is available in the F-Droid app store or in the Play Store.

The exported ".xlsx" or ".csv" result files can also be transferred to a PC for further processing and loaded or imported into a spreadsheet program (tested with MS Excel, LibreOffice Calc and Softmaker PlanMaker).

IT-affine users may transfer the exported ".db" files from "Documents/TransektCount" to a PC.
There you may examine or edit them manually or per SQL script with a free tool like "DB Browser for SQLite"
(https://sqlitebrowser.org).
Some useful example SQL scripts are published in the docs directory of the GitHub TransektCount project site
https://github.com/wistein/TransektCount/tree/master/docs.

Under "App Info" you may find general app info, the email address of the author and the history.

Under "Licenses" you find the license notes for code and figures.

The option menu of the counting page provides a "Photo" function to quickly take a photo and a "Share" function for sending TransektCount related notes using a standard app, like SMS or email.

Optionally, the counter view is temporarily turned off by means of the proximity sensor when the phone is pocketed or closely held to the body. This saves energy, prevents unwanted inputs and recalls the app into its current state immediately when used again.

The app shows several short pop-up messages in 4 categories:

- Error        (e.g. with a database problem).
- Warning (e.g. in the event of an invalid entry).
- Note        (e.g. if an action might last longer).
- Info          (e.g. after a successful process).


5. GPS Usage

Automatic section recognition in the transect is performed by comparing the current position with the track coordinates of the transect sections in a transektcount_xxx.gpx file. If the current position is no further than e.g. 5 m (default setting) away from a section track point, the section is indicated for registration. Contact between two transect sections should be avoided and gaps of approx. 5 m between sections are recommended. GPS inaccuracies may have to be accepted in some cases, but modern smartphones are now very accurate.

The allowed distance from the track "Max. Distance of track deviation" can be set between 2 and 10 m (default: 5 m) to accommodate the device's GPS accuracy.

To strike a balance between performance and power consumption, you can set the "Min. distance for GPS update" between 0 and 5 m (default: 5 m) and the "GPS polling interval" between 1 and 10 seconds (default: 3 seconds).


5.1 Creating the Track File for TransektCount

A transect route can be recorded using a free smartphone app such as CoMaps or another hiking map app that can export the recorded track with sufficient accuracy in GPX format. It is advisable to record the transect route several times on-site with the smartphone. The recorded track should match the route shown on the map. Discrepancies that are similar across repeated recordings of the transect route suggest inaccuracies in the map.

In addition, named waypoints can be set at the section boundaries during recording. The recordings are intended to serve as a guide for the section tracks that will subsequently be drawn manually for a sufficient precision.

On Windows:

You may use the free BaseCamp program from Garmin. Load a suitable free map based on OpenStreetMap. Import the recorded transect GPX track(s).

When manually drawing track sections in BaseCamp, you should use the highest possible zoom level, as this allows you to achieve optimal spacing of approximately 2 meters between individual track points when drawing a track. This ensures sufficient accuracy for coordinate matching to identify sections within the app.

The transect sections must be drawn as new section tracks in the same number and order as they are listed in TransektCount. During import of the created .gpx file in TransektCount, they are assigned to the existing transect sections in this order. Naming them is intended solely for your own reference and is ignored by TransektCount.

Draw each section track with the individual track points spaced approximately 2 meters apart along the imaginary, averaged line of the recorded route. Leave a gap of approximately 5 meters between each section track.

Once all the section tracks are complete, delete the transect GPX route(s) that were previously imported from your smartphone.

The drawn transect tracks can then be exported to the file “transektcount_xxx.gpx”, where the prefix “transektcount” is significant and “xxx” serves as a placeholder for a transect name.

On Linux:

You can use the Viking program for this. Although its user interface differs significantly from BaseCamp, the result is just as useful. The procedure is the same as that described in “On Windows”.

In Viking, the result must be exported as a “Single GPX File”.


5.2 Usage of the Track File in TransektCount

Copy the created transektcount_xxx.gpx track file to "Documents/TransektCount" on the smartphone. There it is expected by the app for import.

If the track file has been created correctly, the "Import GPS Track" command will acknowledge this with the message “The GPX file has been imported.”

Finally, activate the item "Indicate transect section by GPS" under Settings and, if necessary, adjust the sensitivity under "Maximum GPS deviation allowed".

As the number of transect sections must be equal to the number of tracks, adding a new transect section is only possible as long as no tracks have been imported. Therefore, before adding a new transect section existing tracks must be deleted from the database using the "Delete GPS Track Data" function.

After adding a new section, the track file assigned to the transect must also be supplemented with the track of the new section in BaseCamp, Viking or a similar application and reimported into TransektCount.

When a transect section is deleted, the corresponding section track is also deleted from the database.


6. Messages

When attempting to delete a section with a crossed-out delete symbol from the section list:

Section nn: To prevent DB corruption it is not possible to delete this section. Only the last created section may be deleted. (If the last created section cannot be deleted then your device has unfortunately not enough resources to execute this delete function.)

With current models, however, this restriction could only occur with very many transect sections. Other functions of the app are not affected by this restriction.

No possible solution known. See the document "TransektCount_Userguide_nnn.pdf" for further info under
https://github.com/wistein/TransektCount/tree/master/docs.
